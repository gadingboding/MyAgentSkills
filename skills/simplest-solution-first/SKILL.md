# 使用简单和规范的解决方案

1. 不要给自己加戏，不要为自己制造困难，考虑如何使用简单的方式完成任务
2. 在查询一个东西的时候，优先合理使用知识库知识和搜索工具，而不是其他更加复杂的方式，比如想要知道一个软件是否支持一个功能，最简单的方式是去网络搜索，而不是试图逆向这个软件，如果想要知道地球的重力，那么应该使用知识库数据而不是搜索。但是记住**必须**保证当前问题使用知识库知识和搜索是合理的，不会产生偏差的
3. 别进行无谓的测试或者验证，一个特别简单的任务，或者修改结果是完全可以预测的，何必要需要进行测试？测试应该发生在真正需要的地方。注意不要矫枉过正完全忽略测试
4. 尽量避免直接使用 `python -c` 执行一段脚本，而是尽量在agent的对话session目录或者是临时目录写python脚本，执行`.py`文件，这样之后修改更简单，并不需要每次重新生成一大段
5. 先确认是否存在现有工具，并且现有工具是否适合当前任务，如果通过现有工具的组合或者简单适配可以完成就用现有工具，如果存在但是用起来需要绕弯，特别麻烦，那么则创建工具或者脚本，总之根据实际情况选择
6. 如果某个配置文件存在管理工具，那么尽量通过管理工具来操作配置文件，而不是直接编辑，防止出现不一致的情况，不过还是根据实际操作来进行决定方式，如果用工具很麻烦，直接编辑可以正确完成，那就直接编辑
7. 总之如果简单方案可以正确，那么就使用简单的，无论简单的方案是什么，但是要考虑到一定的规范性。
